# AAI-44 Interface SLA Automation — Architecture

## 1. Architecture Overview

The AAI-44 automation follows a hybrid cloud and local execution architecture.

The cloud portion is responsible for receiving and storing the daily report, while the local portion is responsible for executing the Python transformation.

```text
                    CLOUD
        ┌──────────────────────────┐
        │                          │
        │   Outlook / Office 365   │
        │            │             │
        │            ▼             │
        │   Power Automate Flow    │
        │            │             │
        │            ▼             │
        │   OneDrive for Business  │
        │                          │
        └────────────┬─────────────┘
                     │
              OneDrive Sync
                     │
                     ▼
                    LOCAL
        ┌──────────────────────────┐
        │                          │
        │     Windows Machine      │
        │            │             │
        │            ▼             │
        │    Windows Task          │
        │      Scheduler           │
        │            │             │
        │            ▼             │

        │            │             │
        │            ▼             │
        │   Structured Excel       │

        └──────────────────────────┘
```

## 3. Component Responsibilities
Outlook / Office 365
Responsibility:
Receive the daily AAI-44 Interface SLA Report email.
The email acts as the source of the raw report.

Power Automate
Responsibility:
Automatically detect and extract the required CSV attachment.
The flow performs:
1. Email detection.
2. Sender validation.
3. Subject validation.
4. Attachment validation.
5. Inline attachment validation.
6. CSV file validation.
7. Timestamped file naming.
8. OneDrive file creation.
Power Automate does not perform the CSV transformation.

OneDrive for Business
Responsibility:
Provide the storage and synchronization bridge between Power Automate and the local Windows machine.
The cloud flow writes the CSV into:
```
AI Initiatives 2026/Agentic PlayBook/AAI44Input
```
OneDrive synchronizes the file to the local machine.

Windows Task Scheduler
Responsibility:
Automatically start the Python automation at the configured schedule.
The scheduler does not perform data processing itself.
It only launches:
```
Automation.py
```

Python Automation
Responsibility:
Perform the actual AAI-44 report transformation.
The Python script:
1. Identifies the latest CSV.
2. Reads the raw report.
3. Identifies the current Airport / Site.
4. Extracts timestamp.
5. Extracts current utilization.
6. Adds CustomerKey.
7. Creates a structured DataFrame.
8. Generates an Excel file.
9. Moves the successfully processed CSV to the Processed folder.

## 6. Failure Handling
The architecture intentionally separates input, output, and processed files.
If Python processing fails:
```
AAI44Input
     │
     ▼
Python
     │
     X
   Error
     │
     ▼
CSV remains in AAI44Input
```
The input CSV is not moved to the Processed folder.
This allows the file to remain available for investigation and reprocessing.
If the Excel file is successfully created but the CSV cannot be moved, the generated output remains available and a warning is reported.

## 7. Scheduling Architecture
The current implementation uses Windows Task Scheduler to execute the Python script.
The scheduler is configured to run during the expected report-processing window.
The task launches:
```
Python
   ↓
Automation.py
```
The Python script itself determines which CSV should be processed by selecting the latest CSV available in the input folder.
This provides separation between:
- When the automation runs — Task Scheduler
- Which file is processed — Python
- How the file is transformed — Python transformation logic

## 8. Cloud-to-Local Integration
OneDrive is used as the integration point between the cloud workflow and the local automation.
```
Power Automate
      │
      ▼
OneDrive Cloud Folder
      │
      │ Synchronization
      ▼
Local OneDrive Folder
      │
      ▼
Task Scheduler
      │
      ▼

```
This avoids requiring a separate API or cloud-hosted Python execution environment.

## 9. Security Considerations
The repository should contain only the automation code and documentation.
The following must not be committed:
- Customer CSV files
- Generated Excel reports
- Email attachments
- Passwords
- Access tokens
- Client secrets
- Connection strings
- Personal credentials
The .gitignore file prevents common generated report files such as .csv and .xlsx from being committed accidentally.
Local machine paths should be represented using placeholders in shared documentation where appropriate.
Example:
```
C:\Users\<USERNAME>\OneDrive - SITA\...
```
rather than exposing an individual user's local path.

## 10. Architecture Benefits
The architecture provides:
- Reduced manual intervention.
- Automated report collection.
- Automated data transformation.
- Consistent file processing.
- Separation of input, output, and processed files.
- Failure recovery through retention of failed input files.
- Reuse of the existing Python transformation logic.
- No requirement for Azure Functions.
- No requirement for SharePoint.
- No additional application server.
